Pipeline in one paragraph: `buildNiches` -> Gaussian KDE of each cell type per sample, stored as reducedDim `Niche<sigma>` (cells x cellTypes). `fitSpiDE` -> for each index cell type k, one NB GLM per gene over k-cells of all patients with design [patient intercepts (absorbed) | covariates (centred log-lib etc.) | log1p niche densities | (condition x niche, sandwich only)], fitted by SpaNorm::polishNB. Slopes engine: from the shared fit, a one-step Fisher-scoring per-patient slope + two variances (model, spatial-tile sandwich); Sandwich engine: patient-clustered CR2 SE with Bell-McCaffrey df. `testSpiDE` -> slopes engine: DerSimonian-Laird tau2, limma moderated pooled test (eBayes robust + trend) with Kish-scaled df, HC2/Bell-McCaffrey WLS condition test; BH within families. `spiGSEA` -> gene sets as averaged scaled slopes. `testNicheAbundance` -> between-patient pseudobulk limma regression with leverage cap.

- Linear algebra: `solve`, `eigen(symmetric = TRUE)` (eigenvalues descending; eigenvector sign arbitrary but results invariant), `crossprod`, `qr` (LINPACK default, tolerance 1e-7) used for rank tests in `.robustConditionTest` and `.abundancePair`; `chol2inv` inside limma.
- Optimisers: none in spiDE directly. `optimize()` / bisection live inside SpaNorm::polishNB (profile dispersion). No `optim`, no `nls`, no `glm`.
- Parallelism: BiocParallel `bplapply`/`bpnworkers`/`SerialParam`; results are designed to be identical serial vs parallel (tested).

### 2.5 Random numbers
- The inference code (fitSpiDE/testSpiDE/spiGSEA/testNicheAbundance/plots) uses NO RNG. Only: (a) `ggrepel::geom_text_repel(seed = 1)` in plotSpillover; (b) toy-data generators (`.localSeed` + `set.seed`); (c) tests that call `set.seed(k)` to permute condition labels or simulate slopes; (d) the model vignette's schematic figure (`set.seed(7)`).
- Reproducing toySpiDE exactly in Python requires R's Mersenne-Twister + inversion normal + R's `rgamma`, `rnbinom`, `rlnorm`, `sample()` (rejection sampling in R >= 3.6) streams; practical alternative: export the .rda to parquet/npz once and ship it (recommended).

## 7. Porting hazards

### 7.1 R numerical/semantic traps
- **pmax/pmin attribute keeping** (`.dlTau2`): `pmax(x, 0)` keeps dim/dimnames of its first argument (matrix G x nt). `pmax(Q - (m-1) / ..., 0)` with NaN gives NaN (then set to 0 by `!is.finite`); numpy `np.maximum(nan, 0)` = nan (OK) but `np.fmax` = 0 -- use `maximum` then explicit non-finite -> 0. `pmax(neff - k, 1)`, `pmax(rat, 1)`, `pmax(ev, 0)` similar. `pmin(ev$values, 1 - 1e-8)`.
- **apply() over 3-d arrays**: `apply(w, c(1,3), sum)` returns a G x nt matrix (even nt == 1 -> G x 1 matrix; with MARGIN c(1,3) and nt=1 R returns a matrix, but `apply(r, c(2,3), median, na.rm=TRUE)` in `.patientFactor` returns S x nt). In spiGSEA, `.dlTau2(b, v)[, 1]` takes the single niche. Python: use `np.sum(axis=1)`, `np.nanmedian(axis=0)` carefully (nanmedian of all-NaN returns NaN with a warning; R median(na.rm=TRUE) of empty returns NA -> later `!is.finite` handled).
- **column-major array layout**: `.patientSlopes` fills G x (S*nt) matrices with `as.numeric(bb)` where bb is S x nt (patient fastest), then `array(B, c(G,S,nt))`. Reproduce as `arr[g, s, j]`. `expand.grid(g, s, j)` in patientSlopes has g fastest; final output is re-sorted by `order(index, gene, niche, patient)`.
- **string sorting/collation**: sample ids and patients are `sort(unique(...))`, so with ids S1..S16 the order is S1, S10, S11, ..., S16, S2, ... (locale-dependent for mixed case/punctuation: R's `sort` of character uses the locale collation, e.g. en_US ignores case and punctuation in the first pass; `table()` names and `factor()` levels also use `sort`). `order(...)` in the accessors and `.conditionCoding` (`sort(unique(as.character(x)))`) rely on it: "Non-responder" < "Responder" => contrast "Responder - Non-responder". Python `sorted()` is codepoint order; decide on one rule and test with mixed-case names. `order(index, gene, niche, patient)` is multi-key string order.
- **factor level ordering**: `factor(smp[ik])` => sorted levels; `model.matrix(~ 0 + patient)` columns follow levels; `droplevels(factor(strata))` treatment contrast drops the first level (alphabetical); conditions coded 0/1 by `lv[2]`; `factor(cond_s[b$samples], levels = levels(cond_s))`; `.groupLevels` uses contrast order.
- **model.matrix column naming / contrasts**: names `patient:<level>`, `strata:<level>:<niche>` (built manually), `condition:<niche>` (manual), and in `.abundancePair` the interaction column is `niche:condition` (formula `niche * condition`), compared by exact string. A condition recoded to numeric -0.5/+0.5 is a numeric column named "condition".
- **rowsum reorder**: `rowsum(x, group, reorder = TRUE)` sorts groups (here by sort of unique labels, which for tile labels is a character sort of strings like `"S1\r3\r7"`; ordering does not affect `crossprod(Ut)` but does affect nothing else) -- fine; BUT `rowsum(w, pid, reorder = TRUE)` over integer patient codes sorts numerically. `.patientLevels` uses `rowsum(L, pat, reorder = TRUE) / table(pat)`: relies on both being in sorted-level order. `.glmStart` uses `rowsum(t(offset), patient, reorder = TRUE)`.
- **tile keys** use `\r` separators and `floor(coord / tile)` on absolute coordinates (negative coordinates floor toward -inf); tile count `nT = length(unique(tt))` per patient (tiles of all that patient's index cells, across its sections since keys contain `sec`).
- **mean/median NA handling**: `median(..., na.rm = TRUE)`, `rowMeans(..., na.rm=TRUE)`, `rowSums(is.finite(.))`; `rat[!is.finite(rat)] <- 1`; `vt[miss]` logical-matrix assignment; `tt[n_ok < min.pooled | !is.finite(tt)] <- NA` (genes with fewer than 6 usable patients get NA p although they were fit by limma); `p[m < 2 | ...] <- NA`.
- **limma-specific**: weights normalised per row to mean 1 over finite entries; `Amean` replaced after lmFit; `eBayes(trend=TRUE, robust=TRUE)` internally calls `fitFDistRobustly` with `covariate = Amean` using a natural-spline basis of the covariate (df 4) and winsorised F; the tryCatch fallback to `robust = FALSE` triggers on ANY error (e.g. all-NA rows, too few genes) and when both fail all gene results are NA (`suppressWarnings` hides legitimate warnings such as "Zero sample variances detected" and "Partial NA coefficients"). `limma::lmFit` with NAs in `b` switches to the per-gene `lm.wfit` path; rows with <2 usable patients were removed beforehand. `df.total` capping: limma caps `df.total` at the sum of the residual df of non-NA genes.
- **tryCatch fallbacks (silent failure -> NA/gene dropped)**: `.partialBlock` (`solve` error -> NULL -> patient/gene skipped), `.sandwichCR2` (`solve(Info)` error or non-finite -> gene omitted), `.robustConditionTest` (`solve` -> NULL -> NA; all per-gene guard conditions give NA not error), `.abundancePair` (`model.matrix` error -> NULL, `eBayes/lmFit` error -> NULL -> pair dropped), `.pooledColumnTest` (eBayes). A Python port must treat singular matrices (LinAlgError) identically and must replicate thresholds: `1e-12 * colSums(Ls^2 * ws)` (diagonal check), `values[last] <= values[1] * 1e-8` (rank on correlation scale), `values > max * 1e-10` (CR2 patient rank), `1 - 1e-8` (hat clamp, leverage test `h >= 1 - 1e-8`), `1e-3` ridge, `psi.range c(1e-3, 1e3)`, `max.coef = 20`, `rank.tol = 1e-10` (nbBlockDesign), `1e-6`/`1e-3` leverage tolerances, `floor = 0.05`.
- **qr rank decisions**: `qr(X)` default is LINPACK `dqrdc2` (tol 1e-7, columns with small norm moved to the end); `qx$pivot[seq_len(qx$rank)]` selection and `qr(cbind(S1, trt))$rank == qr(S1)$rank` depend on this exact algorithm; use `numpy.linalg.matrix_rank` with tolerance carefully (not equal in edge cases) or implement pivoted QR with the same rule. `.abundancePair` also uses `qr(X)$rank == ncol(X)` and `qr(X * sqrt(w))`.
- **eigen sign/ordering**: `eigen(symmetric=TRUE)` returns decreasing eigenvalues; code uses `e$values[length]` as smallest and `e$values[1]` as largest; numpy `eigh` returns ascending -- reverse. Results are sign-invariant by construction.
- **hat values**: `stats::hat(X, intercept = FALSE)` uses QR; its `max(h)` etc. Equivalent to diag of X (X'X)^-1 X'; for rank-deficient X R's `hat` uses pivoted QR rank.
- **hclust/dist** ordering in plotTripletHeatmap (R's `hclust` leaf order is deterministic but not identical to scipy's `dendrogram` leaf order) -- cosmetic.
- **ggplot2 specifics**: plotmath labels (`label_parsed`, `parse(text=)`), `facet_grid(space = "free_y")`, `scale_size_area`, `geom_curve`, `scale_y_log10`, `ggrepel`; `p$data` contents are documented as API (tests inspect `ggplot_build`). A Python port (plotnine/matplotlib) cannot match these; recommended to treat plots as a separate, lower-priority task.
- **S4**: slots untyped inside lists; `$` forwards to slots; `.isLegacy` is only for RDS compatibility (drop in Python or keep as a version check). `validity` only checks engine and table columns; `methods::new` calls it.
- **sparse/DelayedArray counts**: code never densifies the whole matrix: `Yk %*% sparse indicator`, `Matrix::rowMeans(Y > 0)`, `Matrix::colSums`. Counts in toySpiDE are a dense double matrix. Python: scipy.sparse CSR with the same reductions.
- **BiocParallel gene chunking**: `.bpGenes` uses `cut(seq_len(G), nch)` with `nch = min(G, 4 * nworkers)`; chunking never changes values (verified by tests), so a Python port can parallelise freely.

### 7.2 Stateful / name-encoded things
- **reducedDim names**: `paste0(name, sigma)`, default `"Niche30"`, `"Niche10"`; R formats a double with up to 15 significant digits: `30 -> "30"`, `12.5 -> "12.5"`, `0.1 -> "0.1"`, `1e5 -> "1e+05"`, `100000L -> "100000"`, `1e-4 -> "1e-04"`, `1234567 -> "1234567"`. `.pickSigma()` recovers sigma by regex `^Niche[0-9.]+$` -> `as.numeric(sub(...))`, so names with exponents (e.g. "Niche1e+05") are NOT recognised there (but `checkNiche(paste0(name, sigma))` would find them when sigma is passed explicitly). `buildNiches(sigma = c(10, 30, 50, 70))` makes four. `spiDE()` hard-codes the "Niche" prefix when testing for presence.
- **`metadata(spe)$spiDE_niche_groups`**: named list; key = reducedDim name (`"Niche30"`); value = named list (merged-or-singleton column name -> fine member cell types, composed through earlier merges). Read by fitSpiDE (group_map for `.isSelfNiche`), `.nicheFold`; testNicheAbundance does not read it. mergeNiches with `sigma = NULL` regex-matches every reducedDim starting with `name` (e.g. "Niche" would also match "NicheXYZ" and unrelated dims named like that).
- **SPE contract**: cell types in colData are not sanitised in fitSpiDE (niche columns keep raw names) but `.isSelfNiche` sanitises both sides; testNicheAbundance sanitises cell type labels and niche names (`" "`/`"-"` -> `"."`) so outputs from that function carry sanitised names while fitSpiDE outputs carry raw ones.
- **Patient table & condition**: `SpiDEFit@patients` includes all patient-constant colData columns; `.conditionCoding` reads the condition from it, so a condition can be named at test time. `SpiDEFit@condition` is the column name given at fit time (slopes: just recorded). `params$strata` is recorded and reused by `testSpiDE`.
- **verbose/messages**: `message()` lines in fitSpiDE and testNicheAbundance (tests rarely assert on them; plots emit `message()` for unfitted genes).
- **Seeding side effects**: only the toy generators seed; they restore `.Random.seed`. No package-level options except `options(SpaNorm.polish.mem.budget)` inside SpaNorm.
- **Version-gated behaviours**: fits/results from earlier versions (<= 0.99.33 lack `intercept`, `niche_mean`, `loglib_mean`; <= 0.99.36 results lack `pooled.df` slot and used "capped") are tolerated through `checkIntercepts` and `.pooledDfOf`; legacy (<= 0.99.22) mixed-model objects refused.

### 7.3 Known cross-version numeric choices worth pinning in a port (all in code comments)
- Pooled test df rule "proportional": `df.total * neff / m` where neff = Kish number of the mean-1-normalised weights over finite entries and m the finite count; "capped": `min(df.total, neff - 1)` floored at 1.
- Pooled test weights: `v_model x factor + tau2` with `factor = max(1, median_g v_tile/v_model)`; the condition test uses the same weights (since 0.99.32), HC2 SE with Bell-McCaffrey df and requires Kish n_eff >= 3 per arm.
- Condition-test family: strict `< fdr` on BH q (pooled) or BH-adjusted `p.heterogeneity` computed over all pooled rows with finite heterogeneity p (all index types and niches pooled together, key by gene/index/niche).
- `n_patients` in the pooled test = number of finite slopes; sandwich = `length(x$patients)` (all patients of the index type).
- Gene tested only if detected in >= `min.detect` (0.1) of the index cells (strictly `>=` on `rowMeans(Y > 0)`), index type requires >= `min.patients` (6) patients each with >= `min.cells` (10) cells, and each patient with fewer than `min.cells` cells is dropped before the fit; slope engine additionally skips patients with `< min.cells` index cells (redundant).
- Gene is dropped (all-NA row, absent from sandwich coef) when polishNB flags it unpolished, psi non-finite, any non-finite coefficient, or |non-absorbed coefficient| > 20 (`runaway`).

## Biggest-risk summary (also returned in the hand-off)
1. limma `lmFit` + `eBayes(robust = TRUE, trend = TRUE)` with row-wise NA weights and a custom `Amean` covariate defines the pooled test; no Python equivalent exists (needs a faithful port of `squeezeVar`/`fitFDist`/`fitFDistRobustly`/`.ebayes`, or an rpy2 oracle).
2. `SpaNorm::polishNB` / `nbBlockDesign` / `tpsBasis` are the NB engine; the installed SpaNorm (1.7.10) lacks polishNB, the needed source is SpaNorm 1.7.16 and the sibling spanormpy already ports it (reuse, but check parity of status flags `polished`, `psi_bound`).
3. spatstat `densityfun(edge = TRUE, diggle = TRUE)` Gaussian KDE (exact Diggle edge correction on the sample's bounding-box window, evaluated at all cells, scaled by pi*sigma^2) must be re-implemented exactly; every downstream number depends on it.
4. R-specific semantics: lexicographic sort/factor-level order of patients and conditions, LINPACK `qr` rank/pivot decisions, `pmax` NaN/attribute behaviour, 3-d `apply`, many silent tryCatch/guard thresholds that turn genes into NA, and number-to-string formatting of sigma in `Niche<sigma>`.
5. toySpiDE and all test fixtures depend on R's RNG streams (`.toySPE` uses runif/sample/rnorm/rgamma/rnbinom/rlnorm in a specific order with no short-circuiting); export the rda to a neutral format rather than regenerate, and expect oracle tests (clubSandwich, direct limma) to need frozen reference values.
